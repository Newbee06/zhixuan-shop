## 3. 业务速率与额度换算（估算）

### 3.1 已有应用层限流（实测）

| API | 限制 | 最坏请求贡献（粗算） |
|---|---|---|
| POST 下单成功 | 10 / IP / 10 min | 单 IP ≤ 1440 成功单/天（仍耗 captcha/products） |
| 查单/secret/lookup | 30 / IP / 10 min | 单 IP 刷读有上限 |
| POST `/pay` | 订单 5 + IP 20 / 10 min | 防 TXID 刷 |
| 登录 | IP + 全局失败阈值 | 防爆破 |

### 3.2 未限流或弱限流面（风险）

| 路径 | 风险 | 建议（方案，未实施） |
|---|---|---|
| `GET /` HTML | `no-store`，每次计 Worker 请求 | 评估 Static Assets 或短缓存（**不得**缓存 API 付款态） |
| `GET /api/products`、`/api/config`、`/api/app-icons` | 可被刷 | IP/WAF/Turnstile 或边缘限流（须批准） |
| `GET /api/captcha` | 刷验证码耗 D1 写 | 与 Turnstile 联动、更严限流 |

**标记**：滥用防护对写路径 **PASS**；对读路径打满 100k → **FAIL 风险**。

## 4. Cron 预算

| Cron | UTC | 日次数 | 空闲预期 | 有 pending 预期 |
|---|---|---|---|---|
| `*/1 * * * *` | 每分钟 | 1440 | D1 轻查 + 过期清理；零 RPC | + RPC + 最多 100 单处理 + 游标扫 |
| `0 2 * * *` | 02:00 | 1 | 7 天交付清理 + session + 上游轮询 | 同左 |

**CPU 预算**：每次 cron 必须在 **10 ms CPU** 内完成 JS；网络等待不计入。  
**策略**：保持「无 pending → 零 RPC」；积压时优先缩小批、不要加频。

## 6. 日切与故障行为

| 事件 | 行为 | 运营动作 |
|---|---|---|
| Workers 请求超限 | Error **1027** | 查滥用；必要时 WAF；**不**关支付核验 |
| CPU 超限 | Error **1102** / `exceededCpu` | 缩小 cron 批；查 PBKDF2 路径；讨论 Paid |
| D1 行读/写超限 | 查询失败 | 停非关键批量任务；保留付款路径优先 |
| D1 500MB 满 | 无法写入 | 清理过期交付/审计归档方案（须批准） |

UTC 00:00 重置 Free 日计数；上海时间约为 **08:00**——早晚高峰前看用量。
